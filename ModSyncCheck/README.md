# Mod Sync Check
Blocks a player from joining a multiplayer game until their mods and mod versions match the host's.

**[Download the latest version](https://www.nexusmods.com/stardewvalley/mods/53850)**, then unzip it into your game's `Mods` folder. It needs [SMAPI](https://smapi.io).

- **Host has the mod:** the host checks the joining player's mod list before the game approves them, using the host's settings. A mismatched player never enters the world; the host gets a HUD notice, and the player sees a short reason on their farmhand selection screen even if they don't have the mod, with where to download it. That screen only has room for three lines, so the full list of mismatches is in the host's SMAPI log and in the dialog shown to players who have the mod.
- **Joining player has the mod:** they're disconnected and shown the list in a dialog on the title screen. If the host doesn't have the mod, the joining player checks the host's mod list themselves and leaves if it doesn't match.
- **Both have the mod:** the joining player is offered a download of the mods they're missing or have at a different version, sent directly by the host (the player chooses which; see below). Mods are only added or updated, never removed; a replaced version is moved to `Mods/.ModSyncCheck/backup`, and the player's `config.json` is never changed. The downloaded mods are unpacked into `Mods/.ModSyncCheck/pending` and moved into place when the game closes, so the game must be restarted before joining again.
- **Getting mods without trusting the host:** mods the host has an original archive for (see below), if they have a Nexus Mods update key, are listed as "Verifiable" and the rest as "Unverifiable". Two checkboxes choose what to get: the verifiable mods (ticked to start with), and the unverifiable ones, which needs "I know the host personally and trust them". A verifiable mod is installed only if Nexus Mods confirms it; with the second box ticked, an original file is installed unchecked if Nexus Mods can't be reached. Afterwards the player is shown which mods they still need, with links to Nexus Mods.
- **Changed files from the host:** if a file the host sends as an original doesn't match the mod's files on Nexus Mods, the player is warned that the host changed it. Without trust it's deleted without being unpacked, and the player remembers that mod version for that host, so next time it's listed as unverifiable and the trust checkbox gets the host's version. With trust it's installed, with a warning.
- **Links to Nexus Mods:** in the dialog shown to a blocked player, each mod with a `Nexus:<id>` update key links to its Nexus Mods page, so they can download it themselves instead of trusting the host. The links always go to nexusmods.com; the host only sends the mod's number.
- **Both have the mod, and the joining player's version is older than the host's or a different major version** (like 1.x and 2.x): the joining player is blocked until they have the host's version, which they can download from the host like any other mod. A newer minor or patch version than the host's (like 1.3 when the host has 1.2) is fine.
- The full list is always written to the SMAPI log on whichever side has the mod.
- **Mod managers:** some mod managers, like Stardrop, have SMAPI load mods from their own folder of links to the mods they chose. Mods are then installed, and `.ModSyncCheck` kept, in the folder Mod Sync Check's own link leads into, so they end up with your other mods; a new mod also gets a link in the folder SMAPI loads from, so it's loaded after the restart. The mod manager may not have that mod ticked the next time you start the game from it.
- **Windows, Linux, and macOS:** on Linux and macOS the game is restarted with SMAPI's `StardewValley` launcher, so it opens in a terminal window again, and the downloaded mods are still moved into place after the old terminal window closes.

## Mod archives
The original archives you downloaded your mods in (`.zip`, `.7z`, or `.rar` files) are kept in the archives folder: `Mods/.ModSyncCheck`, or the folder set in `ArchivesFolder`. They're never changed or repacked, so they still match the MD5 hash Nexus Mods has for them.

- **Install mods without unpacking:** put a mod's `.zip`, `.7z`, or `.rar` straight into your `Mods` folder and start the game. Every mod in it is unpacked into the folders the archive has, as if you'd unpacked it, and you're offered a restart to load them. A mod you already have is updated in its current folder, keeping your `config.json`, with the old version moved to `Mods/.ModSyncCheck/backup`; a mod you have at the same or a newer version is left alone. The archive then moves into the archives folder, or is deleted if an archive of the same versions is already there. An archive with no mods in it, or one that couldn't be fully installed, stays in `Mods`.
- **Collected from Stardrop:** each time the game starts, the archives Stardrop downloaded from Nexus Mods (in `%AppData%\Stardrop\Data\Nexus`, or `~/.config/Stardrop/Data/Nexus` on Linux) are moved into the archives folder, or deleted if an archive of the same versions is already there. This needs a version of Stardrop which keeps its downloads after installing them; the official one deletes them straight away. Downloads which aren't `.zip`, `.7z`, or `.rar` files with mods are left for Stardrop to clean up.
- **Sent to joining players unchanged:** when a player needs a mod and the archives folder has an archive with that mod's ID and version, the host sends that file instead of packaging its mod folder. The player checks its MD5 hash with Nexus Mods (no account or API key needed) before unpacking it, and only the mod's own folder in it is installed. Mods without an archive are sent from the host's mod folder, without a check.
- **Old archives deleted:** each time the game starts, an archive in `Mods/.ModSyncCheck` is deleted if another archive there has a newer version of every mod in it. One with the version you have installed is kept until you install the newer one. A folder set in `ArchivesFolder`, like your downloads folder, is never cleaned up.

## Settings
Settings are in `config.json` (created on first launch), and can be edited in-game if [Generic Mod Config Menu](https://www.nexusmods.com/stardewvalley/mods/5098) is installed. Only the host's settings are used when the host has the mod.

| Setting | Default | Effect |
| --- | --- | --- |
| `RequireThisMod` | `true` | When hosting, block players who don't have Mod Sync Check installed, even if their other mods match. They're shown where to download it. |
| `IgnoredModIds` | common client-only mods | Mod IDs which don't need to match. In Generic Mod Config Menu this is the first checkbox next to each installed mod: checked means required, unchecked means ignored. |
| `ArchivesFolder` | empty | The folder with the original archives you downloaded your mods in (see [Mod archives](#mod-archives)), like your Nexus Mods or Vortex downloads folder. It can be a full path or one relative to the `Mods` folder, and can start with `~` for your home folder (like `~/Downloads`); empty means `Mods/.ModSyncCheck`. Only `.zip`, `.7z`, and `.rar` files directly in the folder are used, not subfolders. This can only be changed by editing `config.json`. |
| `UnsyncedConfigModIds` | none | When hosting, the required mods for which players keep their own settings. For every other required mod, players who have this mod use your `config.json` settings while they're in your game. In Generic Mod Config Menu this is the "Sync Config" checkbox next to each mod: checked means players use your settings. Their own settings files aren't changed, and they get their own settings back when they leave. Some mods, like content packs, can't change their settings while the game is running, so players keep their own for those. |
| `SyncedConfigModIds` | none | When hosting, the ignored mods for which players use your settings anyway, if they have the mod. This is the same checkbox, for a mod which isn't required. |
| `NeverSyncedConfigModIds` | none | Mods whose settings are never sent to players, whatever the other settings say. Their "Sync Config" checkbox is greyed out; this list can only be changed by editing `config.json`. |

Mods which only the joining player has are always allowed.

The host's settings stay in force for the whole session. If a player changes one of those settings mid-game it's changed back within a few seconds, and if the mod saved its settings in the meantime the player's `config.json` is put back as it was. If the host changes its own settings mid-game, the players in the game switch to the new ones.
